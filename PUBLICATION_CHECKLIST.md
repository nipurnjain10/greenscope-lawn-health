# Publication checklist

The dataset and the code in this folder are not yet published at a public URL. Do not write a repository link into the report until the group has created the repository and the link opens.

## Before creating the repository

- [ ] Fill `group_info.json` with the real group number, five names, and five enrollment numbers.
- [ ] Replace each contribution sentence only after that member confirms the sentence. Do not leave the bracketed placeholders.
- [ ] Run `python -m src.build_documents`.
- [ ] Open `submission/PROJECT_REPORT.docx`, check the contribution table, and write the printed page numbers next to each contribution.
- [ ] Confirm `submission/PROJECT_PRESENTATION.pptx` opens and that the charts match `reports/model_metrics.json`.
- [ ] Confirm `DATA_SOURCES.md` still says that no external table was downloaded.
- [ ] Remove `.venv/`, `__pycache__/`, `.pytest_cache/`, and `.matplotlib/` from anything you upload. They are listed in `.gitignore`.
- [ ] Do not upload `output/assessment_history.json` if anyone typed identifying notes into an assessment.

## Create the group's own repository

1. Create an empty repository in the group's own account. This project does not already have a public remote.
2. From the project root, initialise git if it is not already a repository, add the project files, and commit.
3. Add the new repository as `origin` and push the default branch.
4. Open the repository in a browser and confirm that `data/synthetic_lawn_inspections.csv`, `app.py`, `README.md`, and `submission/PROJECT_REPORT.md` are visible.
5. Copy the repository URL only after that page loads.

## After the URL exists

- [ ] Paste the real URL into the report's data-availability paragraph and into this checklist.
- [ ] State the licence the group chooses. Do not copy a licence from a dataset that was not used.
- [ ] Say again, next to the URL, that the CSV is synthetic and was generated by `data/generate_synthetic_data.py`.
- [ ] Rebuild the documents if the report text changed.
